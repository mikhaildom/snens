# Десктоп-приложение snens

Оболочка Tauri 2: окно с веб-клиентом и ядро `snens` как дочерний процесс.
Один установщик, одно обновление — ядро, тулы и клиент едут внутри бандла.

## Раскладка после установки (Windows, per-user, без UAC)

```
%LOCALAPPDATA%\snens\
├── snens-desktop.exe      # окно (Tauri)
├── snens.exe              # ядро: HTTP/API + статика клиента (sidecar)
├── memory.exe             # плагин долгой памяти (sidecar)
├── tools\                 # тулы: read, edit, run-инструменты, shot, web, desk…
│   ├── read\read.exe
│   └── …
└── web\                   # собранный клиент (dist из snens-web)
    ├── index.html
    └── assets\…
```

Данные и конфиг — как у обычного snens (`%APPDATA%\snens`): установка их не
касается, удаление их не трогает.

## Почему так

- **Ядро — sidecar, а не сервис.** На Windows служба требует администратора и
  живёт в сессии 0, где нет ни профиля пользователя, ни UI. Поэтому ядро —
  обычный дочерний процесс окна, с `CREATE_NO_WINDOW`: консольного окна нет, а
  жизнь процесса привязана к окну через job object с `KILL_ON_JOB_CLOSE`.
- **Обновление одно на всё.** Sidecar'ы — часть бандла, поэтому
  `tauri-plugin-updater` тянет новый `-setup.exe`, а тот перезаписывает и
  `snens.exe`, и тулы, и `web\`. Никакой сборки на машине человека: cargo, node
  и rustc в поставке не нужны.
- **Один процесс отдаёт и API, и клиент.** `snens serve` умеет `ServeDir` на
  `web\` (см. `SNENS_WEB_DIR` в ядре), поэтому отдельный vite/npx в поставке не
  участвует — это была бы dev-зависимость в продукте.

## Пейринг: ядро на другом устройстве

Оболочка умеет работать в двух режимах:

1. **Локальное ядро** (по умолчанию): поднимает sidecar на свободном порту и
   открывает окно на нём.
2. **Удалённое ядро**: окно показывает экран подключения (адрес + код из
   `snens pair` на сервере), сохраняет полученный токен в защищённое хранилище
   ОС и дальше работает с чужим адресом. Своего ядра в этом режиме не запускает.

Токен в web-view попадает через `window.__SNENS__ = {baseUrl, token}`, который
оболочка выставляет после загрузки окна: в бандл клиента секрет не попадает.

## Сборка

```sh
# 1. Клиент
cd ../snens-web && npm ci && npm run build      # → dist/

# 2. Бинари ядра и тулов, с суффиксом target-triple (требование Tauri sidecar)
cd ../snens && cargo build --release --workspace
scripts/desktop-stage.sh                        # раскладывает binaries/ и resources/

# 3. Приложение
cd desktop && npm ci && npx tauri build
```

`scripts/desktop-stage.sh` — единственное место, где записано соответствие
«что куда кладётся»: бинарники получают суффикс `-<target-triple>`, клиент
копируется в `resources/web`.

## Что осталось проверить на живой Windows

- Регистрация автозапуска (плагин `autostart`, HKCU Run) — права обычного
  пользователя.
- Поведение NSIS при обновлении, когда ядро держит файлы: его надо гасить до
  запуска инсталлятора, иначе Restart Manager его не увидит (он знает только
  главный exe).
