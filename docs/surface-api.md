# Дашборд инстанса: тикеты и ревью-сессии (surface API)

Два read-only маршрута для дашборда. Источник у обоих — файлы инстанса:
`tickets/*.md` и журналы `<session>-review.jsonl` рядом с сессиями. Ничего не
создаётся и не правится: единственный писатель журнала держит отдельный `.lock`,
и чтение его не касается.

Оба ответа — объект с единственным ключом-массивом, как у `/v1/search`
(`{"hits":[…]}`): формат оставляет место соседним полям (счётчики, курсор), не
ломая клиента.

## `GET /v1/tickets`

Тикеты инстанса, свежие сверху. Открытые и закрытые вместе — `status` есть в
строке, фильтрует клиент (ядро не угадывает, что нужно дашборду).

```json
{
  "tickets": [
    {
      "name": "2026-09-22-edit-multi-hunk",
      "status": "done",
      "kind": "opportunity",
      "target": "edit",
      "family": "правка исходников — одна логическая правка, разнесённая по нескольким местам файла",
      "weight": "2",
      "hits": 1,
      "symptom": "Одна логическая правка требует двух вызовов `edit`: сначала аккумулятор в цикле",
      "mtime": 1792766659
    }
  ]
}
```

| поле | смысл |
|---|---|
| `name` | имя файла без `.md` (в нём дата создания) |
| `status` | `open` / `doing` / `done` / `wontfix` — из front-matter, как есть |
| `kind` | `defect` / `opportunity` / `harness` / `workflow` |
| `target` | к чему тикет: тул, `harness`, `workflow` |
| `family` | семейство задач (заполняется у `opportunity`), может быть пустым |
| `weight` | заявленная тяжесть, **строкой** — как написано в файле (поле свободное) |
| `hits` | **число**, разобранное из `hits:`; нет или мусор — `0` |
| `symptom` | первая непустая строка секции `## Симптом`, обрезана до 200 символов |
| `mtime` | время правки файла, unix-секунды |

Сортировка — по `mtime` убыв., при равенстве по `name`: имя это дата создания,
а дописанная «История» делает старый тикет свежим, и список должен это
показывать. `mtime`, а не дата из имени — единственный признак, который видит
и дописывание.

## `GET /v1/tickets/{name}`

Тело одного тикета целиком, как он лежит на диске (front-matter включён).

```json
{"name": "2026-09-22-edit-multi-hunk", "body": "---\nstatus: done\n…\n## Симптом / что повторяется\n…"}
```

- `name` — ровно имя файла без `.md`. Префиксы и поиск по тексту остаются в CLI
  (`snens tickets show`, `tickets grep`): неоднозначность — дело человека, а не
  маршрута.
- Нет такого тикета — `404 {"error":{"code":"not_found",…}}`.
- Имя с `/`, `..` или точкой в начале — `400 invalid`, не `404`: маршрут имени
  не принимает вовсе (иначе `../` читал бы файлы вне каталога).

## `GET /v1/reviews`

Ревью-сессии инстанса, свежие сверху. Ревью — не отдельное хранилище, а журнал
`<id>-review` рядом с сессиями: в его шапке `Rec::Replay` ссылается на сессию-
источник, а тело — реплика-инструкция (та же, что в `prompts/review.md`) и
ответы модели. Отсюда все поля.

```json
{
  "reviews": [
    {
      "id": "1792709015-60910-review",
      "session": "1792709015-60910",
      "ts": 1792709275,
      "status": "ok",
      "summary": "Ревью готово.\n\n**Новый тикет:** `tickets/2026-10-22-who-killed-service.md` — …"
    }
  ]
}
```

| поле | смысл |
|---|---|
| `id` | id ревью-сессии: `<session>-review` |
| `session` | сессия-источник из `Rec::Replay.session`; ссылка битая — имя из файла |
| `ts` | когда ревью запустили: время записи с `source: "review"` (инструкция дописывается каждым прогоном, в отличие от `Meta.ts`); нет такой — `Meta.ts`, затем mtime файла |
| `status` | исход по факту: `Rec::Done.status` (`ok` / `error`); записи нет — `running` |
| `summary` | первые 300 символов финального (последнего непустого) ответа ассистента |

Отдельного «вердикта» ревью в журнале нет: итог — это его текст, он и уезжает в
`summary`. `Done` пишет харнесс на любом пути выхода, поэтому `running` честно
означает «ещё идёт или процесс убили» — различать эти два случая по журналу
нечем.

Обход — по именам файлов (`*-review.jsonl`), а не по содержимому: полный список
читает шапку каждого журнала, но не раскрывает префикс из источника (читать
мегабайты чужого лога ради списка незачем). На инстансе с 80 ревью это
единицы миллисекунд; дорогая часть всё равно в `spawn_blocking`, как у
`/v1/search`.
