# Файловые тулы: typed-схема, fuzzy-правка, рабочий каталог

Почему контракт тулов выглядит так, а не generic `args` + JSON на stdin.
Дизайн, измеренные числа и отвергнутые варианты.

## Измеренная картина (802 лога сессий)

Числа собраны скриптом по журналам сессий: вызовы по тулам, отказы по причинам.

| | вызовов | отказов | главная причина |
|---|---|---|---|
| `run` | 20210 | 1280 | не про файлы: код возврата `;`-цепочки, dash |
| `edit` | 4256 | 240 | 95 — разбор JSON на stdin, 123 — `old_string не найден` |
| `read` | 3442 | 316 | 258 — относительный путь после `cd` в `run` |
| `write` | 792 | 6 | |

Плюс **1672** вызова `run` с `python3 - <<'PY'` и 203 с `sed -i` — правка файла
скриптом вместо тула. Это не привычка модели: это цена контракта.

## Корень: содержимое файла едет строкой внутри JSON-строки

Generic-схема реестра — `args` (argv) плюс `stdin: string`. Содержательная часть
правки уезжает в `stdin` как JSON: `{"args":["path"],"stdin":"{\"old_string\":\"…\\n…\"}"}`.
Модель генерирует два уровня экранирования на глаз, второй никем не проверяется до
парсера. Отсюда все четыре класса отказа `edit`: сырые `\n`, незаэкранированные `"`
в коде, `trailing comma`, обрыв входа.

Ремонт «почти-JSON» (три попытки разбора в `tools/edit`) эти отказы просадил, но не
убрал: 22 (25.09) → 26 (08.10) → 8 (12.10) → 4 (17.10) → 4 (18.10, trailing comma).
Эвристика бьётся о следующий вид кривизны, а не о корень. Поэтому ремонт остаётся как
fallback для CLI, а не как путь для модели.

## Решение 1: тул объявляет схему (`tools/<имя>/schema.json`)

Тул — отдельный бинарник, но у него появляется декларация интерфейса; ядро строит из
неё `parameters` OpenAI-функции и само собирает argv/stdin. Модель видит настоящие поля
(`path`, `offset`, `limit` / `path`, `content`, `append` / `path`, `old_string`,
`new_string`), второго уровня экранирования больше нет: JSON собирает `serde_json`.

Формат: JSON Schema объекта плюс ключ расширения `x-snens`:

```json
{
  "type": "object",
  "properties": { "path": {"type":"string","description":"…"} },
  "required": ["path"],
  "x-snens": {
    "argv": [
      {"field": "path"},
      {"flag": "--offset", "field": "offset"},
      {"flag": "--append", "when_field": "append"}
    ],
    "stdin": {"mode": "none"}
  }
}
```

- `{"field": X}` — значение поля отдельным argv-элементом;
- `{"flag": F, "field": X}` — `[F, value]`, если поле передано;
- `{"flag": F, "when_field": B}` — `[F]`, если `B == true`;
- `stdin.mode`: `none` | `field` (сырое значение поля, для `write`) | `json` (объект из
  перечисленных полей, сериализованный ядром, для `edit`).

Нет `schema.json` → тул остаётся generic (обратная совместимость: `fetch`, `search`,
`agent`, `audit`, `view`, `memory`). Терпимость к кривому вводу сохранена по образцу pi:
JSON-строка вместо массива парсится, одиночный объект вместо `edits[]` принимается.

Почему схема в туле, а не в ядре: новый тул не требует правки `src/`, а сам тул
остаётся самостоятельным бинарником — контракт у него один на модель (`schema.json`) и
на человека (`--help`), но объявлен декларативно, без компиляции в ядро.

## Решение 2: fuzzy-матчинг в `edit`

`old_string` сначала ищется точно (как раньше). Не найден — повторный поиск по
нормализованному тексту: `trim_end` по строкам, CRLF→LF, NFKC и замена кривых кавычек,
тире, неразрывного пробела. При совпадении в нормализованном пространстве **на диск
пишутся только изменённые строки**, остальные копируются из оригинала байт в байт —
иначе fuzzy-правка молча нормализовала бы весь файл. В событии `"fuzzy": true`.

Батч `{"edits":[…]}`: все `old_string` матчатся против **исходного** файла, пересечения
запрещены, применяется разом. Последовательное применение (правка N+1 ищет в результате
N) ломалось, как только две правки оказывались рядом.

## Решение 3: рабочий каталог — состояние сессии

`cd` внутри `run` не переносился на `read`/`edit`/`write`: у каждого процесса свой cwd.
258 отказов `read` — ровно это. Каталог хранится в `<sessions>/<id>.out/cwd` (лениво,
нет файла — каталог инстанса), обновляется из `run --cwd` и из эвристики по `cd` в
начале команды (консервативно: сомнение — не обновлять), передаётся детям как cwd и как
`SNENS_CWD`. Резолв относительных путей — от cwd сессии, как в shell.

## Отвергнуто

- **Диагностика после правок (LSP)** — место в цикле хода, а не в тулах;
  к fuzzy-правке не относится.
- **Типизированные тулы в ядре** (`builtin_defs` для read/write/edit) — быстрее на день,
  но каждый новый тул потом снова через правку ядра и релиз. Оставлено как аргумент
  сравнения, не как решение.
- **Учить модель экранировать `\n`** — отвергнуто в `2026-09-24-edit-stdin-json-newlines`:
  признак не выводится из сообщения парсера, а ход теряется на каждой многострочной правке.
- **`grep --outline` в `read`** (`2026-09-24-read-outline`) — не развилка схемы; вынесено
  отдельным тулом `grep`.

## Как проверять эффект

`tool-metrics.py` по логам до/после: `edit`-отказы разбора → 0, `old_string не найден`
→ минус большинство, `read: не найден (относительный)` → почти 0, доля python-heredoc
в `run` — падение в разы. Мерить на живых сессиях, а не на selftest.
