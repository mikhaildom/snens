# Бэклог

## Диагностика после правок (LSP/линтеры)

Место — **не в `edit`/`write`**, а в цикле харнесса: после любого хода, оставившего
грязные файлы (`git status --porcelain`), гонять чекер по расширению изменённых файлов
и приклеивать диагностику к наблюдению. Тогда это работает и для `run sed -i`, а не
только для тулов правки.

- Соответствие «расширение → команда» берётся из `snens.toml` в корне проекта,
  найденного подъёмом вверх от изменённого файла.
- Чекеры — CLI (`cargo check --message-format short`, `tsc --noEmit`, `oxlint`),
  не LSP-демон: демон — это ещё один постоянный процесс ради того же текста.
- Потолок наивной версии: без git-репозитория диагностика не работает; повторный
  запуск чекера на неизменившихся файлах тратится зря.

## Прочее

- `read`/`edit`/`write` написаны на python3 — переписать на Rust, когда контракт
  перестанет меняться.
- Тулы живут в репозитории харнесса; вынести каждый в свой репозиторий, когда
  появится ревью-цикл с issue на тул.
- Read-before-write внутри `edit` не делаем: при неограниченном `run` это театр,
  а не гарантия.
