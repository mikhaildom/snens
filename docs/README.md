# docs/ — дизайн-заметки, а не документация

Каталог для разработчика: почему механизм сделан именно так, какие альтернативы
отвергнуты и чем это обосновано (замеры, прогоны, грабли). Читать их имеет смысл
только перед правкой соответствующего места в коде.

- `context.md`, `review.md`, `subagents.md`, `tools-typed-schema.md`, `pairing.md`,
  `surface-api.md`, `surface-config.md` — устройство подсистем и отвергнутые пути.
- `roadmap/` — планы того, чего в дереве нет. В шапке файла стоит статус.
- `agent-docs.md` — как устроен и как выкладывается сайт документации.

Публичная документация живёт отдельно и отсюда не генерируется:
`site/snens.svuvi.ch/content/` — страницы для человека, `site/snens.svuvi.ch/llm/` —
те же факты плейнтекстом для агентов. Устройство сайта — `docs/agent-docs.md`.

Правило: сюда не попадают личные адреса, порты, имена моделей и история
«раньше было иначе». Расхождение с кодом — ошибка здесь, а не в коде.
