# Долгая память

Память — **плагин, а не сервис**: отдельный бинарь `tools/memory`, один файл
SQLite (FTS5 + sqlite-vec), без демона и без Postgres. Ядро знает только
argv-контракт:

```sh
memory recall <текст>        # → строки фактов (пусто = нечего сказать)
memory retain < ход.json     # {"user":"…","assistant":"…"} → очередь
memory flush                 # очередь → факты (LLM + эмбеддинги)
memory stats | reindex | forget <uid>
```

## Что в поставке

- Плагин — член workspace (`tools/memory`), его бинарь собирается тем же
  `snens build [<тул>…]`, что и остальные тулы, и уезжает в установщик.
- Включён по умолчанию: `[memory]` отсутствует → `enabled = true`,
  `recall = "always"`, `retain = true`, `cmd = "memory"`. Нет бинаря — канала
  нет (тихо, без ошибки хода).
- Свой конфиг плагина — `~/.config/snens/memory.toml`; ключ берётся из того же
  `.env` рядом с конфигом ядра. Провайдер нужен OpenAI-совместимый
  (`/embeddings`, `/chat/completions`), реранк — `/rerank` или `rerank = "off"`.
- Апгрейд из старой версии: плагина, положенного вручную (`tools/memory/memory`
  симлинком на чужой репозиторий), больше нет — он стал частью дерева, и
  `snens build` перезаписывает его как обычный тул.

## Почему не в системном промпте целиком

Справка уезжает в префикс и остаётся там до конца сессии, поэтому она короткая
(`max_facts`, `max_tokens` в `memory.toml`) и впрыскивается по режиму
`memory.recall`: `always` — на каждый ход, `session` — один раз на сессию,
`off` — только по вызову тула.

## Ретенция

`retain` пишет ход в очередь банка: это сетевой вызов и запись в чужой стек,
поэтому для простого чата его выключают (`memory_retain = false` в настройках
или `snens memory retain off`). Дистилляция очереди в факты — `memory flush`
(её зовут извне: таймером или руками).
