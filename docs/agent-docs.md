# Документация для агентов: docs.svuvi.ch

Первичный источник сведений о самом snens — статический сайт плейнтекста. Его читает
агент, а не человек: markdown как есть (`text/plain`), ни вёрстки, ни JS, стабильные
URL. Ссылка на точку входа есть в дефолтном системном промпте (`src/prompt.rs`,
`fn default_system`) — модель узнаёт о ней из префикса, а не из догадки.

- Живой сайт: <https://docs.svuvi.ch/index.txt>
- Контент в репозитории: `site/docs.svuvi.ch/`
- Выкладка: `scripts/docs-site.sh`; генератор справки по тулам: `scripts/docs-tools.py`
- Раздаёт Caddy из `/var/www/docs.svuvi.ch` (блок в `/etc/caddy/Caddyfile` заводит
  человек: агент этот файл не правит).

## Зачем

`docs/*.md` — дизайн-документы для разработчика: почему сделано так, замеры,
отвергнутые альтернативы. Агенту, который работает в snens, нужно другое — контракт
инструментов, конвенции чтения кода, официальные плагины, практики контекста и
привилегий, — и это должно быть доступно по сети, чтобы не зависеть от того, лежит ли
репозиторий на машине и в какой он версии. Отсюда отдельный сайт из пяти файлов,
написанных для чтения моделью.

## Файлы

| файл | что |
|---|---|
| `index.txt` | точка входа: что такое snens, оглавление с полными URL, правила чтения |
| `quickstart.txt` | цикл агента, `run`/`ctx`, тулы реестра, конвенции, файлы инстанса, каталоги |
| `tools.txt` | **генерируется**: `run`, `ctx` и 13 тулов — полный `--help` + поля `schema.json` |
| `plugins.txt` | долгая память (`tools/memory`, snens-memory), скиллы (`SKILL.md`), тулы как репозитории |
| `practices.txt` | контекст и компакция, подагенты, тикеты, память, sudo/брокер, чего не делать |

`tools.txt` руками не правится. Его собирает `scripts/docs-tools.py` из источников,
которые и есть правда: `const HELP` в `tools/*/src/*.rs`, `tools/*/schema.json` и
встроенные `run`/`ctx` из `src/dispatch.rs`. Изменил справку тула — перегенерируй.

## Как обновлять

```sh
scripts/docs-tools.py --write site/docs.svuvi.ch/tools.txt   # только справка тулов
scripts/docs-site.sh --check                                 # проверка без записи
scripts/docs-site.sh                                          # собрать и выложить
```

`scripts/docs-site.sh` в порядке работы:

1. перегенерирует `tools.txt` (если есть генератор; `--no-gen` — только сверяет, что
   файл не устарел: устаревший `tools.txt` хуже отсутствующего);
2. проверяет, что все пять файлов на месте, непустые (>200 Б), без NUL-байтов и без
   html-обвязки, и что каждый файл упомянут в `index.txt` полным URL;
3. копирует файлы в `SNENS_DOCS_WEBROOT` (дефолт `/var/www/docs.svuvi.ch`) через
   temp+mv, чтобы читатель не увидел полуфайл, и печатает таблицу «файл, байты, URL».

Флаги: `--check` (только проверка), `--dry-run` (план без записи), `--no-gen`.
Переменные: `SNENS_DOCS_WEBROOT` (куда копировать), `SNENS_DOCS_URL` (базовый URL в
выводе и в проверке `index.txt`), `SNENS_REPO` (репозиторий, если скрипт зовут не из
него). Sudo скрипт не зовёт и сервис не перезапускает: `/var/www` пишется агентом,
`/etc` — нет.

Локальная проверка без прода:

```sh
SNENS_DOCS_WEBROOT=/tmp/docs-test scripts/docs-site.sh
curl -s file:///tmp/docs-test/index.txt | head    # или python3 -m http.server в нём
```

Проверка снаружи после выкладки:

```sh
curl -sI --max-time 8 https://docs.svuvi.ch/index.txt
curl -s https://docs.svuvi.ch/tools.txt | grep -c '^### '   # 15 секций
```

## Границы

- Сайт — только факты о snens. Ни истории инстанса, ни тикетов, ни заметок сессий:
  `soul.md`/`user.md`/`memory.md` и `tickets/` живут в каталоге данных и не публикуются.
- Отдельной версионности нет: файлы выкладываются из текущего дерева и описывают
  текущий `main`.
- Caddyfile, DNS и юниты — не здесь: домен на wildcard `*.svuvi.ch`, блок в конфиге
  Caddy заводит человек (образец — `models.svuvi.ch`).
