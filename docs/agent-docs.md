# Сайт snens.svuvi.ch

Один домен на весь продукт: лендинг (`/`), документация для человека
(`/docs/*.html`), те же факты плейнтекстом для агентов (`/llm/*.txt`), установщики
и манифест обновления (`/releases/*`).

- Живой сайт: <https://snens.svuvi.ch/>
- Контент в репозитории: `site/snens.svuvi.ch/`
- Сборка и выкладка: `scripts/site-publish.sh` (внутри — `scripts/site.py`)
- Справка по тулам: `scripts/docs-tools.py` — генерируется, руками не правится
- Раздаёт Caddy из `/var/www/snens.svuvi.ch` (блок в `/etc/caddy/Caddyfile` заводит
  человек: агент этот файл не правит, см. `deploy/CADDY.md`)

## Два контура, один источник фактов

| каталог | что | кому |
|---|---|---|
| `content/*.md` | человеческие страницы: установка, конфиг, команды, отказы | человек в браузере |
| `llm/*.txt` | контракт тулов, конвенции, практики | агент через `fetch`/`curl` |
| `asset/style.css` | оформление: та же палитра, что у веб-клиента | — |

Это не две документации, а две подачи одного знания: страница для человека и
машинный файл описывают одно и то же, и расхождение — ошибка. Поэтому HTML руками
не пишется вообще: `scripts/site.py` собирает его из markdown своим минимальным
рендерером (заголовки, списки, таблицы, код, ссылки — большего в текстах нет).

`llm/tools.txt` — единственный генерируемый файл: его собирает `docs-tools.py` из
`const HELP` тулов, их `schema.json` и встроенных `run`/`ctx` в `src/dispatch.rs`.
Изменил справку тула — пересобери сайт, скрипт сделает это сам.

## Почему плейнтекст отдельным каталогом

Агенту нужен стабильный адрес и текст без вёрстки: он читает `llm/index.txt` из
системного промпта (`docs_url` в конфиге) и идёт по ссылкам внутри. Держать
плейнтекст рядом с каждой страницей (`/docs/install.txt`) значило бы поддерживать
два имени одного файла; отдельный каталог — одно имя и явная граница: `/docs/` —
человеку, `/llm/` — модели.

## Как обновлять

```sh
scripts/site-publish.sh --check     # проверить контент, ничего не писать
scripts/site-publish.sh --dry-run   # собрать во временный каталог
scripts/site-publish.sh             # собрать, выложить в /var/www/snens.svuvi.ch
```

Проверка (в том числе при `--check`) валит сборку, если страница короче 200 байт,
не начинается с `# `, оставила плейсхолдер `{{…}}`, если в `llm/` нет файла из
списка `LLM_FILES` или `llm/index.txt` не ссылается на остальные файлы.

Установщик на лендинге не вписан руками: `site.py` берёт адрес из
`/var/www/snens.svuvi.ch/releases/latest.json` и подставляет в `{{INSTALLER}}`.
Нет манифеста — ссылка ведёт на `/releases/`, а не на битый путь.

## Проверка после выкладки

```sh
curl -sS https://snens.svuvi.ch/ | head -20
curl -sS https://snens.svuvi.ch/llm/index.txt | head -20
curl -sS https://snens.svuvi.ch/releases/latest.json | head -5
```

## Старые имена

`docs.svuvi.ch` и `releases.svuvi.ch` уводятся 301 на тот же путь нового домена
(блоки в `deploy/caddy-sites.conf`). Обратной совместимости в коде нет: старые
адреса живут только как редирект.
