# Артефакт: генеративный UI в ответе модели

Артефакт — это интерактивный интерфейс, который модель пишет прямо в ответе:

````
```artifact id=quiz
<!doctype html>
…html…
```
````

Содержимое фенса — либо HTML целиком, либо `src=<путь>` — ссылка на файл,
который модель положила в каталог сессии (`<id>.out/…`).

## Зачем фенс в тексте, а не отдельная запись журнала

Артефакт живёт в `Rec::Assistant.text` обычным markdown. Поэтому:

- стрим не требует новых событий: незакрытый фенс — это состояние парсера на
  клиенте, а `assistant.delta` уже есть;
- история и стрим рисуются одним и тем же парсером (правило `lenta.ts`);
- HTML уже в префиксе промпта: провайдеру он не платится второй раз.

Цена честная: контекст раздувается, и лечится это уборкой — при элизии
результатов фенс схлопывается в строку вида `артефакт quiz: 61 строка`.

## Заголовок

Первая строка тела фенса — заголовок: `ключ=значение`, ключи через пробел,
всё в одну строку. Необязательные ключи не пишутся; неизвестный ключ —
ошибка (иначе опечатка молча ничего не делает).

| ключ | смысл |
|---|---|
| `id` | имя артефакта внутри хода; по нему человек и модель на него ссылаются. Повтор с тем же `id` в том же сообщении — это `rev+1` (правка), клиент показывает последнюю |
| `src` | путь к файлу вместо тела. Тело при этом пустое |
| `net` | домены, к которым артефакту разрешена сеть (`net=api.example.com,cdn.example.com`). Без него — `connect-src 'none'` |
| `height` | желаемая высота в px (дефолт — по содержимому, до 70vh) |

Заголовок — только до первого перевода строки. Всё дальше — тело как есть.

## Грамматика (точная)

Фенс открывается строкой, которая начинается с трёх и более бэктиков и имеет
инфо-строку `artifact` (с опциональным заголовком после пробела). Закрывается
строкой из такого же или большего числа бэктиков. Внутри закрывающей строкой
считается только строка, состоящая из бэктиков и пробелов.

Регулярка заголовка: `^([a-z]+)=(\S*)$` на каждый токен, разделитель — пробелы.
`id` и `net` — `[A-Za-z0-9._-]+`, `net` — через запятую.

Незакрытый фенс (модель ещё печатает) — валиден и означает «артефакт в
процессе»: клиент показывает заготовку, `genui check` считает это ошибкой.

## Изоляция

Артефакт исполняется в `iframe sandbox="allow-scripts allow-forms"` —
**без `allow-same-origin`**: origin `null`, нет cookies, `localStorage` и
доступа к `/v1/*`. Дополнительно в документ вставляется CSP:

```
default-src 'none';
style-src 'unsafe-inline';
img-src https: data: blob:;
font-src data:;
media-src data: blob:;
script-src 'unsafe-inline';
connect-src <net или 'none'>;
```

Правила сети:

- по умолчанию `'none'` — без сети живёт большинство артефактов (квизы,
  таблицы, графики на данных из preload);
- `net=` открывает только перечисленные домены;
- **запрещены всегда**: `localhost`, `127.0.0.0/8`, `10.0.0.0/8`,
  `192.168.0.0/16`, `172.16.0.0/12`, `*.local`, `file:` — иначе артефакт,
  исполняющийся в браузере человека, ходит по его локальной сети;
- к ядру (`/v1/*`) артефакт не ходит никогда: данные приходят preload'ом.

Доверие к модели — не аргумент против песочницы. Разница с инструментами: `run`
исполняется, пока модель работает, а артефакт переисполняется каждый раз, когда
человек открывает сессию, уже без модели. Песочница — то, что делает доверие
допустимым, а не то, что ему противоречит.

## Обмен с хостом

В артефакт инжектится шим (`window.snens`):

```js
snens.data                 // preload: объект, который вставил хост
snens.ask({ id, kind, question, options })
snens.send(text)           // то же, что ask с kind: "text"
```

`ask` → `postMessage` в родителя; родитель проверяет `event.source` и
`event.origin === "null"`. Ответ человека уезжает в чат обычным сообщением
сессии с `source: "artifact"` и ссылкой на артефакт; повторный ответ на тот же
вопрос ядро отвергает (`409 ask_answered`).

## Живая прорисовка

Пока фенс не закрыт, клиент обновляет документ с backoff (0.5 → 1 → 2 с) и
**без скриптов** (`sandbox` без `allow-scripts`): половина скрипта в свежем
документе падает в консоль и мигает. Закрылся фенс — перемонтируем с
`allow-scripts`, это уже полноценный артефакт.

Каждое обновление — новый документ: состояние и анимации перезапускаются,
поэтому артефакт пишется так, чтобы первый осмысленный кадр был уже на скелете.

## Библиотека компонентов

`~/.local/share/snens/genui/`:

```
lib.js            базовые стили и утилиты, инжектится всегда
components/*.js   по одному custom element на файл
INDEX.md          что есть — его читает скилл и `genui list`
```

Библиотека инжектится в каждый артефакт **всегда** и всегда свежая: правка
компонента меняет и старые артефакты. Ключ `lib=<hash>` в заголовке
зарезервирован на случай, если это станет проблемой.

## Проверка

`genui check <session>:<seq>` вынимает артефакт из журнала и проверяет ровно
то, что увидит человек: lint (чужие теги, приватная сеть, размер, незакрытый
фенс) и браузер (рендер в той же песочнице, `console.error`, исключения, битые
картинки, снимок в канал вложений). Нет браузера — деградация до lint с явной
строкой в отчёте.
