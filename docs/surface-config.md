# Настройки инстанса и живые состояния сессий (surface API)

Срез: меню настроек, которое меняет конфиг **без рестарта сервиса**, и живой
список подагентов. Механизм один на всё: процесс поверхности перечитывает
конфиг из файла на каждом ходу (`Config::live`), поэтому любая правка файла —
из UI, `snens config`, руками — действует со следующего хода.

## `GET /v1/config`

Текущие значения правимых ключей (читаются из файла, не из снимка старта):

```json
{
  "path": "/home/user/.config/snens/config.toml",
  "values": {
    "model": "vendor/model-name",
    "subagent_model": "",
    "max_turns": 200,
    "review_min_turns": 20,
    "review_idle_seconds": 600,
    "timeout_seconds": 120,
    "max_result_chars": 24000,
    "reduce_output": true,
    "attachments": true,
    "ctx_window": 1000000,
    "context_budget": 0,
    "context_target": 0,
    "memory_enabled": true,
    "memory_recall": "always",
    "memory_retain": true,
    "memory_cmd": "memory"
  }
}
```

- `max_turns = 0` — **без лимита ходов** (цикл не упирается в потолок; защитой
  остаются бюджет контекста и поведение провайдера). В UI это галочка
  «без лимита»: включена — уходит `0`, выключена — прежнее число (дефолт 200).
- `context_budget`/`context_target` = 0 — авто по окну модели. `context_target`
  без явного `context_budget` отвергается (400): предел авто-режима знает только
  ядро, и обещать число, которое молча обрежется, нельзя.
- `subagent_model: ""` — «как основная»: ключ из файла **удаляется**, а не
  пишется пустой строкой (с ней подагент уходил моделью с пустым именем).
- `memory_recall` — `always` | `session` | `off`.
- `memory_cmd` — имя штатного плагина (`memory`, он в поставке) или путь к
  своему бинарю со слэшем. Имени нет в каталоге тулов — канала нет, и это не
  ошибка: память просто выключена для этого инстанса.

## `PUT /v1/config`

Тело — подмножество `values` (`{"max_turns": 0}`). Ответ — та же структура, что
у GET (актуальные значения после правки). Ошибки: `400 invalid` — неизвестный
ключ, неверный тип или недопустимое значение; `500 config` — файл не записался
или перестал разбираться (тогда правка откатывается: пишем только после успешной
проверки, как `snens model`).

Правка идёт документом TOML (`toml_edit`, `src/cfg_edit.rs`): комментарии,
порядок полей и многострочные строки человека остаются. Ключа нет — он
добавляется (top-level — до первой секции, `memory_*` — внутрь `[memory]`).
Значения с управляющими символами отвергаются до записи; сама запись атомарная
(временный файл → проверка разбора → `rename`), поэтому сломанного конфига на
диске не бывает даже на миг.

Действие: **со следующего хода** той сессии, где он начнётся. Активный ход не
перезапускается.

## `GET /v1/events`

SSE-поток изменений списка сессий (не транскрипта). Кадр:

```
data: {"type":"session.updated","session":{ ...Session из GET /v1/sessions... }}
```

Поверхность публикует его, когда меняется состояние сессии: старт/конец хода,
изменение карточки подагента (ходы, `state`, `done` — не чаще одного кадра на
пачку событий), подхват новой сессии. Клиенту не нужен
опрос: он делает upsert по `id` и держит порядок «свежие сверху» по
`updated_at`. При обрыве `EventSource` переподключается сам; полный список
перечитывается на старте, поэтому пропуск кадра не теряет данные.

## Поля сессии, которые появились для подагентов

`GET /v1/sessions` (и кадр `/v1/events`) для сессии с `parent`:

| поле | смысл |
|---|---|
| `parent` | id родителя — иерархия строится по нему, цепочки любой глубины |
| `state` | `running` — процесс ребёнка жив и работает; `idle` — закрылся нормально; `failed` — упал по лимиту/ошибке; `interrupted` — процесса нет, а `Done` не записан |
| `turns` | сколько ответов модели прошло |
| `done` | `ok` / `limit` / … — последняя запись `Done` |
| `started_at` | unix-время первой записи журнала (когда подагент стартовал) |
| `done_at` | unix-время записи `Done` (когда закончил); пусто — ещё работает |

Длительность: `done_at - started_at` у закрытого, `now - started_at` у
работающего. Считает клиент — ядро отдаёт только границы.
