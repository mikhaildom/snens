snens: документация для агентов
================================

Единственный первичный источник сведений о snens для агентов, которые в нём работают.
Файлы — обычный текст по стабильным URL. Ни вёрстки, ни JS: читай как есть
(`fetch <url>` или `run curl -s <url>`).

Что такое snens. Узкое ядро агента-харнесса на Rust (репозиторий
https://git.svuvi.ch/svuvich/snens): ядро держит цикл «запрос модели → вызов
инструмента → результат», а всё остальное вынесено наружу. Инструменты — отдельные
программы-бинари (argv + stdin), которые ядро находит в каталоге тулов и описывает
модели по их же `--help` и `schema.json`. Два инструмента вшиты в ядро: `run`
(выполнить shell-команду, sh -c) и `ctx` (управление рабочим контекстом). Инстанс
агента — файлы: `soul.md`, `user.md`, `memory.md`, каталог `skills/`, тикеты —
уезжают в каждую сессию.

С чего начать: этот файл → quickstart.txt → tools.txt по нужному инструменту.
Если вопрос про сам snens (как устроен, какие есть инструменты, официальные
плагины, как правильно работать) — читай эти файлы сперва, потом отвечай.

Файлы
-----

index.txt
  Точка входа: что такое snens, оглавление, это описание.
  https://docs.svuvi.ch/index.txt

quickstart.txt
  Как работает агент: тулы и `run`, конвенции чтения кода, файлы инстанса, каталоги.
  https://docs.svuvi.ch/quickstart.txt

tools.txt
  Справочник по всем инструментам: `run`, `ctx` и 13 тулов реестра — полный `--help`
  и поля `schema.json`. Сгенерирован из исходников.
  https://docs.svuvi.ch/tools.txt

plugins.txt
  Официальные плагины и расширения: долгая память, скиллы (формат SKILL.md),
  тулы как самостоятельные программы и репозитории.
  https://docs.svuvi.ch/plugins.txt

practices.txt
  Лучшие практики: контекст и компакция (`ctx`), подагенты, тикеты, память,
  sudo и брокер привилегий, чего не делать.
  https://docs.svuvi.ch/practices.txt

Правила чтения
--------------

- Файл читается целиком, но код — нет: сперва `grep -n` по символу, потом `read
  --offset/--limit` по найденному месту.
- Факты здесь первой руки: они собраны из исходников snens (src/, tools/*, docs/*),
  а не пересказаны по памяти. Расхождение с кодом — ошибка здесь, а не в коде.
- Версия: файлы обновляются вместе с репозиторием, выкладывает их
  `scripts/docs-site.sh`. Ссылки на конкретные версии не ведутся — считай, что
  читаешь текущий `main`.
