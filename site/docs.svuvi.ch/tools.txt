tools.txt — справочник по инструментам snens
Источник: --help тулов (tools/*/src), tools/*/schema.json, встроенные run и ctx (src/dispatch.rs). Сгенерировано scripts/docs-tools.py — руками не править. URL: https://docs.svuvi.ch/tools.txt

## Встроенные в ядро

### run

Выполнить shell-команду (sh -c) и получить вывод: stdout, затем stderr, и код возврата.
run <команда> [--cwd каталог]
Оболочка — sh (dash), не bash: нет ${x:0:n}, [[ ]], массивов, $'\t'; нужен bash — зови `bash -c '...'`. Код возврата при `;`-цепочке — от последней команды, поэтому хвостовой `which`/`grep` может покрасить успешную команду в ошибку (для bash-измов это частая причина).

### ctx

Управление рабочим контекстом. commit — применить правку LIVE_CONTEXT.json (после всех результатов шага; статус придёт перед следующим запросом). status — путь и бюджет. clear — хирургически вырезать результаты инструментов, не трогая диалог: либо call_ids (точечно), либо before (всё строго до указанного), либо keep_last (все старше последних N), с масками tool и min_bytes.

## Тулы реестра

### agent

agent — подагенты snens: запустить, ждать, спросить, ответить, посмотреть.
agent start "задача" | wait <id> [--timeout S] [--progress S] | status <id> | result <id>
      ask [<id>|--parent] [--timeout S] "вопрос" | send <id> "текст" | peers
      broadcast "текст" | list | kill <id>

Подагент — отдельная сессия snens со своим логом. start возвращает её id (печатает
в stdout). Надёжный признак конца — запись Done в логе ребёнка, её пишет харнесс:
даже если ребёнок не отчитался, wait её увидит. Контекст (SNENS_SESSION,
SNENS_MAIL_DIR, SNENS_PARENT) харнесс передаёт переменными окружения.

status — неблокирующий снимок: жив/готов, число ходов, последний вызов инструмента,
сколько секунд назад была запись в логе. wait печатает прогресс раз в 30 с
(--progress S). Коды выхода wait: 0 — Done, 3 — истёк таймаут («ещё работает»),
4 — в моём ящике вопрос (kind=ask): он напечатан в stdout, на него отвечают
`agent send <id> "..."`, вопрос остаётся в ящике и доедет до хода сам.

list — дерево: родитель (^), братья (=), я (>), дети (-) с состоянием, числом
ходов и временем последней записи. peers — id братьев построчно. ask без id
спрашивает родителя (обратная совместимость); ответ ждём только от адресата.
broadcast шлёт steer всем братьям и родителю.

Контракт: generic — args (array|string) + stdin (string); разбор argv делает сам тул.

### audit

audit — разобрать лог сессии: таймлайн вызовов и подозрительные места.
audit <лог.jsonl> [--huge N]

Таймлайн показывает, что и в каком порядке делалось: повторяемая форма работы видна
в нём и тогда, когда ошибок нет. Подозреваемые — детерминированные счётчики:
duplicate, retry-storm, huge, failed-abandoned. Разделы печатаются всегда: молчание
неотличимо от «не смотрел».

Контракт: generic — args (array|string) + stdin (string); разбор argv делает сам тул.

### desk

desk — не браузер: окна и приложения машины пользователя через дерево доступности.
desk <команда> … [--tunnel user@machine]

desk launch [--port N]                 поднять агента на той машине в сессии пользователя
desk stop                              остановить агента
desk apps                              окна: индекс, заголовок, класс, pid, рамка
desk snap [--window W] [--full]         дерево окна с адресами e1…eN (файл + счётчики)
desk act --json '<действия>' [--window W]  действия по адресам: click/set/toggle/focus/type/keys
desk shot [--window W] [--out файл]     скриншот окна (почти всегда нужен для canvas)
desk focus [--window W]                 вывести окно на передний план
desk status                             что запущено на той стороне

  --window W   выбор окна: индекс из `apps` (0,1,2…), подстрока заголовка, или пусто = в фокусе
  --tunnel     машина, где живёт агент (ssh). Агент запускается `desk launch`

Устройство: на машине пользователя работает долгий процесс в ЕГО интерактивной
сессии (из ssh система видит ноль окон — проверено), мы говорим с ним по
JSON-строке через ssh-туннель. Снимок дерева уходит в файл, в контекст — путь,
счётчики и первые строки. Адреса e1…eN живут до следующего `snap`.

Приоритет: если задача в браузере — это `web` (CDP дешевле и точнее). `desk` — для
всего, что вне браузера: мессенджеры, файловые менеджеры, диалоги ОС, canvas.

Коды: 0 — успех, 2 — неверные аргументы, 1 — ошибка выполнения.

Поля (schema.json):
- command: string, обязательное — Что сделать. apps — список окон; snap — дерево окна с адресами e1…eN; act — действия по адресам батчем; shot — скриншот окна; focus — поднять окно; launch/stop — поднять или остановить агента на той машине; значения: launch|stop|apps|snap|act|shot|focus|status
- window: string — Выбор окна: индекс из apps (0,1,2…), подстрока заголовка, или пусто — окно в фокусе
- json: string — Для act: JSON-массив действий по адресам, напр. [{"click":"e3"},{"set":{"ref":"e1","text":"hi"}}]
- tunnel: string, обязательное — Машина, где живёт агент (ssh): например user@machine. Нужна для любой команды
- out: string — Для shot: путь к PNG
- port: integer — Порт агента (дефолт 9227)
stdin: none

### edit

edit — заменить точный фрагмент файла (exact match, как Edit/str_replace).
edit <путь>   — либо old_string + new_string, либо edits[...] (JSON на stdin у самого тула)

Требует ровно одного совпадения old_string, иначе ошибка со списком строк.
Совпадение: точно, затем с точностью до хвостовых пробелов/CRLF/юникода.
Правки edits матчатся против ИСХОДНОГО файла и не должны пересекаться.
Пишет атомарно (temp + rename). --dry-run показывает затронутый участок и не пишет.
В stdout — одна строка JSON-события.

Многострочные значения можно подавать как есть, с реальными переводами строк
внутри кавычек: сырые управляющие символы (перевод строки, таб) чинятся сами,
экранировать их бэкслешем не нужно.

Поля (schema.json):
- path: string, обязательное — Файл для правки: абсолютный или относительно рабочего каталога
- old_string: string — Точный фрагмент, который надо заменить. Должен встречаться ровно один раз, если replace_all не задан. Многострочный текст подавай как есть, с реальными переводами строк.
- new_string: string — Чем заменить old_string
- replace_all: boolean — Заменить все совпадения old_string, а не требовать единственного
- edits: array — Несколько правок одного файла одним вызовом: применяются по порядку и атомарно. Вместо old_string/new_string.
stdin: json (объект из полей old_string, new_string, replace_all, edits)

### fetch

fetch — прочитать веб-страницу как markdown.
fetch <url> [--raw] [--fallback auto|never|always] [--save путь] [--max-chars N] [--timeout S]

Свой путь: GET с браузерным User-Agent, очистка DOM (script/nav/header/footer/…),
<main>/<article> в приоритете, затем markdown. Не-html (pdf и бинарь) сливается в файл.

  --raw              не чистить DOM, конвертировать всё body
  --fallback MODE    auto (дефолт) — r.jina.ai при 403/429 или пустом результате;
                     never — никогда; always — сразу только r.jina.ai
  --save путь        куда слить не-html (иначе каталог SNENS_ATTACH_DIR)
  --max-chars N      обрезать вывод (дефолт 40000)
  --timeout S        таймаут запроса, секунды (дефолт 30)

PDF при наличии системного pdftotext извлекается в текст (если нет --save).

Контракт: generic — args (array|string) + stdin (string); разбор argv делает сам тул.

### grep

grep — поиск по файлам: путь, строка, текст совпадения.
grep <шаблон> [<путь>...] [--glob G] [--context N] [--limit N] [--ignore-case] [--word] [--files-only] [--no-ignore]

Поиск литеральный (регулярок нет): --word — только целым словом, --ignore-case — без
учёта регистра. Обход рекурсивный; по умолчанию пропускаются каталоги
.git/target/node_modules/…, файлы > 1 МБ и бинарные (--no-ignore снимает пропуск
каталогов). Печатает `путь:строка: текст`, при --context N соседние строки —
`путь:строка- текст`. Нет совпадений — код 0 и строка «нет совпадений».

Поля (schema.json):
- pattern: string, обязательное — Что искать. Поиск литеральный (без регулярок): текст как есть; --word/--ignore-case меняют правило сравнения.
- path: array — Каталог или файл для поиска. По умолчанию текущий (.). Каталоги обходятся рекурсивно; .git, target, node_modules, .venv, dist, build, bin и файлы > 1 МБ пропускаются.
- glob: array — Фильтр по имени файла: `*` и `?`, например '*.rs'. Можно несколько раз.
- context: integer — Сколько соседних строк показать вокруг совпадения; они идут с префиксом `путь:строка-`.
- limit: integer — Максимум совпадений в выводе (по умолчанию 200). При обрезке печатается пометка «обрезано: показано N из M».
- ignore_case: boolean — Не учитывать регистр.
- word: boolean — Искать только целое слово: dispatch не совпадёт с dispatch_tool.
- files_only: boolean — Печатать только имена файлов с совпадениями.
stdin: none

### memory

memory — долгая память агента (SQLite + FTS5 + sqlite-vec)
memory recall <запрос> | memory retain | memory flush | memory stats | memory reindex | memory forget <uid>

recall  — гибридный поиск: BM25 ∪ вектор → RRF → реранк → порог; по строке на факт.
retain  — ход (JSON {"user","assistant"} на stdin) в очередь на дистилляцию.
flush   — разобрать очередь: извлечь факты, погасить противоречащие, слить дубли.
stats   — сколько живых фактов, устаревших, что в очереди.
reindex — посчитать вектора для фактов, записанных без провайдера.
forget  — закрыть факт по uid (остаётся в таймлайне, но не выдаётся).

Настройки: ~/.config/snens/memory.toml (db, api_base, embed_model, rerank,
rerank_model, max_facts, max_tokens), ключ — SNENS_API_KEY в ~/.config/snens/.env.

Контракт: generic — args (array|string) + stdin (string); разбор argv делает сам тул.

### read

read — прочитать текстовый файл с номерами строк (формат cat -n).
read <путь> [--offset N] [--limit M] [--max-chars N]

Номера строк нужны, чтобы ссылаться на место правки. По умолчанию 400 строк.
Бинарные файлы отклоняются. Для каталога — `run ls`.

Поля (schema.json):
- path: string, обязательное — Файл для чтения: абсолютный или относительно рабочего каталога. Ведущий ~ разворачивается.
- offset: integer — С какой строки начать (1-based, по умолчанию 1)
- limit: integer — Сколько строк показать (по умолчанию 400)
- max_chars: integer — Потолок символов в ответе (по умолчанию 40000)
stdin: none

### search

search — веб-поиск через SearXNG: заголовок, ссылка и сниппет на каждый результат.
search <запрос> [--n N] [--page P] [--lang L] [--fresh day|week|month|year] [--category general|news|it] [--site домен] [--json]

По умолчанию 10 результатов (максимум 30), вывод человекочитаемый: три строки
на результат и футер со счётчиками. --json — нормализованный JSON одной строкой.
Адрес: SEARXNG_URL или url в ~/.config/snens/search.toml (дефолт http://127.0.0.1:8888).

Контракт: generic — args (array|string) + stdin (string); разбор argv делает сам тул.

### shot

shot — снять скриншот страницы headless-хромом: элемент по селектору, кроп, JS-проба.
shot <url> [--size WxH[,WxH...]] [--selector CSS] [--crop X,Y,W,H] [--script файл.js] [--no-shot] [--wait-ms N] [--timeout S] [--chrome путь] [--out-dir каталог]

Открывает URL в headless Chrome (CDP по ws://127.0.0.1), снимает PNG и кладёт файл
в канал вложений харнесса (SNENS_ATTACH_DIR) — оттуда картинка уезжает в контекст.

  --size WxH         размер окна; несколько через запятую (дефолт 1440x900):
                     `--size 1440x900,390x844` — десктоп и мобильный кадр за запуск
  --selector CSS     снять рамку элемента через CDP и отдать кроп именно его
  --crop X,Y,W,H     явный кроп (CSS-пиксели документа)
  --script файл.js   выполнить JS на странице и напечатать JSON результата.
                     Содержимое файла — тело async-функции: значение возвращается
                     через return, напр. `return {title: document.title}`.
  --no-shot          только JS-проба: картинку не снимать (экономит вложение)
  --wait-ms N        пауза после загрузки, мс (дефолт 300)
  --timeout S        внутренний таймаут всего запуска, секунды (дефолт 20)
  --out-dir каталог  куда класть PNG (дефолт — временный каталог, удаляется)

С `--script` без снимка действует как DOM-проба: probe-HTML в проекте не нужен.
Chrome берётся из --chrome, SNENS_CHROME, ~/.cache/ms-playwright/chromium-*/chrome-linux64/chrome
или PATH (chrome, chrome-headless-shell, chromium).

Коды: 0 — успех, 2 — неверные аргументы, 1 — ошибка выполнения (включая таймаут).

Поля (schema.json):
- url: string, обязательное — Адрес страницы, только http/https
- selector: string — CSS-селектор элемента: рамка считается в браузере (getBoundingClientRect), отдаётся кроп именно этого элемента. Взаимоисключающе с crop
- size: string — Размер окна WxH, несколько через запятую: '1440x900,390x844' (дефолт 1440x900)
- crop: string — Явный кроп X,Y,W,H в CSS-пикселях документа (когда селектора нет)
- script: string — Путь к .js: содержимое исполняется как тело async-функции на странице, в stdout печатается JSON результата. Так проверяется поведение без probe-HTML
- wait_ms: integer — Пауза после загрузки, мс (дефолт 300)
- timeout: number — Внутренний таймаут запуска в секундах (дефолт 20): по истечении тул возвращает ошибку, а не висит
stdin: none

view — показать модели изображение с диска (PNG/JPEG/GIF/WebP).

Картинка уезжает в контекст как изображение, а не текстом. Без канала вложений

### web

web — браузер машины пользователя через CDP: дерево с адресами, действия батчем, скриншот как fallback.
web connect|status|tabs|use|open|snap|act|shot|eval|text|probe|disconnect|launch|show|close [аргументы]

Соединение — к Chrome, разрешённому для отладки по согласию
(chrome://inspect/#remote-debugging, Chrome 144+), или к отдельному профилю агента.

web connect [--port N]                 найти Chrome и запомнить порт (env SNENS_CDP_PORT)
web connect --tunnel user@machine       то же к Chrome на другой машине через ssh
web status                             что сейчас подключено и какие вкладки открыты
web open <url> [--new]                 перейти в текущей вкладке (или открыть новую)
web tabs [--all]                       список вкладок; --all — включая чужие
web use <tabId|N>                      переключиться на вкладку по id или номеру из tabs
web snap [--depth N] [--full]          снимок дерева доступности: файл + счётчики, адреса e1…eN
web act --json '<действия>' [--no-snap]  действия по адресам батчем: click/type/set/press/scroll/hover/select/navigate/wait
web shot [--full] [--out файл]         скриншот вкладки (fallback и верификация)
web eval <выражение>                   выполнить JS на странице (проверка, извлечение)
web text [--limit N]                   видимый текст страницы (дешёвое чтение)
web probe                              проверить, что ввод реально доставляется (клик/клавиша/вставка)
web close                              закрыть текущую вкладку и снять привязку
web disconnect                         закрыть ssh-туннель (Chrome и вкладки не трогаем)
web launch [--profile путь] [--port N] [--visible]  запустить ОТДЕЛЬНЫЙ профиль Chrome
                                       на машине пользователя: без подтверждений, переживает ssh.
                                       --visible — в сессии пользователя, чтобы окно было видно
web show                               вывести окно агентского Chrome на экран (Windows)

--tunnel user@machine                  говорить с Chrome на той машине через ssh-туннель:
                                       на той стороне web НЕ нужен, только Chrome с согласием
--host user@machine                    выполнить ту же команду на другой машине по ssh
                                       (там тоже должен стоять web; вывод — как локально)

Проверка с машины пользователя, где ничего не установлено:
  web connect --tunnel user@machine        # ssh -L к его Chrome, порт 9222
  web snap / web act …                        # дальше как обычно, туннель уже поднят
  web disconnect                              # закрыть туннель

Снимок дерева НЕ уезжает в вывод целиком: печатаются путь к файлу, число узлов
и первые строки — остальное читается через grep/read. Действие возвращает
дельту состояния, а не всё дерево заново. Адреса живут до следующего `snap`.

Порядок предпочтения: CDP-действие (дёшево, без пикселей) → дерево → скриншот
и координаты только там, где дерева нет (canvas, чужое приложение).

Порты/соединение: --port, SNENS_CDP_PORT, иначе 9222. Chrome 136+ игнорирует
--remote-debugging-port на дефолтном профиле: нужен тумблер в chrome://inspect
или отдельный профиль агента.

Коды: 0 — успех, 2 — неверные аргументы, 1 — ошибка выполнения (включая таймаут).

Поля (schema.json):
- command: string, обязательное — Что сделать. connect — найти Chrome (тумблер в chrome://inspect/#remote-debugging); open — перейти; snap — снять дерево с адресами; act — действия батчем по адресам; text — видимый текст; shot — скриншот; eval — JS; probe — проверить, что ввод доставляется; значения: connect|status|tabs|use|open|snap|act|shot|eval|text|probe|disconnect|launch|close
- url: string — Адрес для open (только http/https/file)
- tab: string — Вкладка для use: id (или его начало) либо номер из tabs
- json: string — Для act: JSON-массив действий, напр. [{"click":"e3"},{"type":{"ref":"e1","text":"hi"}},{"press":"Enter"}]. Действия: click/hover (адрес или [x,y]), type {ref,text}, clear, press, scroll, navigate, wait, upload {ref,file}, eval
- expr: string — Для eval: JS-выражение; результат печатается как есть (объект — JSON)
- limit: integer — Для text: сколько символов отдать (дефолт 4000)
- depth: integer — Для snap: максимальная глубина дерева (дефолт 30)
- out: string — Для shot: путь к PNG (дефолт — канал вложений или каталог состояния)
- port: integer — Порт CDP (дефолт 9222 или порт из состояния connect)
- host: string — Машина пользователя для ssh: та же команда выполняется там (там тоже должен стоять web). Пример: user@machine
- profile: string — Для launch: каталог профиля Chrome на той машине (по умолчанию ~/.snens-chrome). Отдельный профиль = отладка без подтверждений
- tunnel: string — Машина пользователя для ssh-туннеля к её Chrome: на той стороне web ставить не нужно, только Chrome с включённым тумблером в chrome://inspect/#remote-debugging. Пример: user@machine. Дальше все команды идут через туннель
stdin: none

### write

write — записать файл целиком, содержимое берётся со stdin.
write <путь> [--append]

Для новых файлов и полной перезаписи. Точечные правки — через edit.
Создаёт родительские каталоги, пишет атомарно. В stdout — JSON-событие.

Поля (schema.json):
- path: string, обязательное — Файл для записи: абсолютный или относительно рабочего каталога. Родительские каталоги создаются.
- content: string, обязательное — Содержимое целиком: уходит на stdin как есть, без JSON-обёртки и без экранирования
- append: boolean — Дописать в конец вместо перезаписи
stdin: field (сырое значение поля content)

Всего: 13 тулов реестра + 2 встроенных.
